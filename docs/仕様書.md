# 401号室 予約管理システム 仕様書

会議室「401号室」の予約を Google アカウントで管理する Web アプリケーション。
月/週/日表示のカレンダーで予約を作成・確認でき、予約者本人の Google カレンダー連携や
Slack 通知（オプション）にも対応する。

- 最終更新: 2026-07-11
- 対象リポジトリ: モノレポ（`frontend/` + `backend/`）

---

## 1. システム概要

| 項目 | 内容 |
|---|---|
| 目的 | 401号室の予約を一元管理し、重複予約を防止する |
| 利用者 | `@pluslab.org` ドメインの Google アカウント保有者のみ |
| 認証 | Google OAuth 2.0（ドメイン制限あり） |
| 予約単位 | 1室・排他利用（同時間帯に複数予約は不可） |
| 利用可能時間 | 9:00 〜 22:00（同日内で完結する予約のみ） |
| タイムゾーン | Asia/Tokyo で統一 |

                               │ OAuth / API
                               ▼
                   ┌───────────────────────┐
                   │ Google OAuth /         │

                   └───────────────────────┘

- `docker-compose.yaml` で 3 サービス（`db` / `yoyaku`(backend) / `frontend`）を一括起動。
- フロントは `withCredentials: true` でセッション Cookie を送受信し、CORS は `http://localhost:3000` を許可。

## 3. 機能仕様

### 3.1 認証・ログイン

| 機能 | 内容 |
|---|---|
| ログイン | `/login` → Google OAuth 開始。`/callback` でユーザー情報を取得しセッション発行 |
| ドメイン制限 | メールが `@pluslab.org` 以外は `/login?error=domain` へリダイレクトし拒否 |
| ユーザー登録 | 初回ログイン時に `users` へ自動登録（`FindOrCreateUser`） |
| セッション | `gorilla/sessions` の Cookie ストア。`SECRET_KEY` で署名 |
| セッション復元 | Cookie に `user_id` が無くても、他のセッション値からユーザーを再作成して復旧（`utils/auth.go`） |
| ログアウト | `POST /api/logout` で Cookie を失効（`MaxAge = -1`） |
| 取得スコープ | `userinfo.email` / `userinfo.profile` / `calendar.events` |
| リフレッシュトークン | オフラインアクセス＋再同意（consent）を強制して確実に取得。本人カレンダー連携に使用 |

> エラー時の遷移先: 認証失敗 `/login?error=true`、ドメイン不許可 `/login?error=domain`

### 3.2 予約の作成

- 画面: 「新規予約」ボタン、または週/日ビューの時間枠クリックでモーダルを開く。
- 入力項目: タイトル（既定「面接」）/ 日付 / 開始時刻（時・分、5分刻み）/ 所要時間（30・60・90・120分）/ 備考。
- 終了時刻は「開始時刻 + 所要時間」で自動計算。
- フロント・バックエンド双方で以下のバリデーションを実施（後述 §5）。
- 成功時は再フェッチしてカレンダーへ即時反映。

### 3.3 予約の編集・キャンセル

| 操作 | 場所 | 挙動 |
|---|---|---|
| 編集 | マイページの予約カード → 編集モーダル | タイトル・日時・備考を更新。作成者本人・`confirmed` 状態のみ |
| キャンセル | マイページの予約カード | `status` を `canceled` に更新（論理キャンセル、レコードは残す） |

- 編集・作成いずれも重複チェックを実施（編集時は自分自身のレコードを除外）。
- 終了済み予約は編集・キャンセルボタンを非表示。

### 3.4 カレンダー表示

- ライブラリ: Schedule-X（月グリッド / 週 / 日）。ヘッダーのボタンで切替、`currentView` を `localStorage` に保存し再訪時に復元。
- 表示範囲に応じ `GET /api/reservations?start=&end=` で取得（`confirmed` のみ）。
- カレンダー上のイベント名は**予約者名**を優先表示（`user_name || title`）。
- 月セルの高さから 1 日あたり表示件数を動的算出（ResizeObserver）。溢れは「他 N件」表示。
- 日本語化: Schedule-X の `jaJP` 翻訳辞書を全面上書き。
- 稼働時間帯 `dayBoundaries: 09:00–22:00`、週の開始は日曜（`firstDayOfWeek: 7`）。

### 3.5 マイページ

- ユーザー情報（アバター・表示名・メール）を表示。
- **表示名の編集**: インライン編集（最大50文字、`PUT /api/me`）。セッションの `user_name` も同期。
- 自分の予約を状態別に整理して表示:
  - 「現在・今後の予約」= 開始が近い順（進行中が先頭）
  - 「終了した予約」= 直近に終わった順
- 状態バッジ: `開始前` / `進行中` / `終了`（現在時刻から算出）。

### 3.6 Google カレンダー連携・通知

| 機能 | トリガー | 条件 | 失敗時の扱い |
|---|---|---|---|
| 本人カレンダー登録 | 予約作成時 `add_to_google_calendar: true` | 本人の refresh token 保有 | 予約自体は成功。結果を `google_calendar` フィールドで返す |
| 共有カレンダー同期 | 予約作成時（常時） | `GOOGLE_CALENDAR_SYNC_ENABLED=true` かつ サービスアカウント設定 | ログのみ、予約は成功 |
| Slack 通知 | 予約作成時・キャンセル時（常時） | `SLACK_NOTIFY_ENABLED=true` かつ `SLACK_WEBHOOK_URL` 設定 | ログのみ、予約操作は成功 |

本人カレンダー連携の結果ステータス:

| 値 | 意味 |
|---|---|
| `added` | 本人カレンダーに作成成功 |
| `needs_relogin` | refresh token が無く再ログインが必要 |
| `failed` | 連携失敗 |
| `""`（空） | 連携を要求していない |

### 3.7 PWA

- `manifest.webmanifest`（`display: standalone`、アイコン 192/512/maskable）。
- Service Worker（`/sw.js`）:
  - API（`/api`）・認証（`/login`, `/callback`）・別オリジンはキャッシュせず常にネットワーク。
  - ページ遷移はネットワーク優先、失敗時は `/offline.html` へフォールバック。
  - 静的アセットはキャッシュ優先。

## 4. データモデル

### `users`

| カラム | 型 | 説明 |
|---|---|---|
| `id` | BIGSERIAL PK | ユーザーID |
| `name` | VARCHAR(255) | 表示名 |
| `email` | VARCHAR(255) UNIQUE | メール（ログイン識別） |
| `google_id` | VARCHAR(255) UNIQUE | Google のユーザーID |
| `avatar_url` | TEXT | アバター画像URL |
| `google_refresh_token` | TEXT | 本人カレンダー連携用トークン |
| `role` | VARCHAR(50) | 既定 `user` |
| `created_at` / `updated_at` | TIMESTAMPTZ | 監査用 |
| `deleted_at` | TIMESTAMPTZ | 論理削除 |

### `reservations`

| カラム | 型 | 説明 |
|---|---|---|
| `id` | BIGSERIAL PK | 予約ID |
| `user_id` | BIGINT FK→users | 予約者 |
| `title` | VARCHAR(255) | タイトル |
| `start_time` / `end_time` | TIMESTAMPTZ | 予約時間帯 |
| `status` | VARCHAR(50) | `confirmed`（既定）/ `canceled` |
| `notes` | TEXT | 備考（既定 空文字） |
| `google_event_id` | TEXT | 連携時の Google イベントID（キャンセル同期用） |
| `created_at` / `updated_at` | TIMESTAMPTZ | 監査用 |

- インデックス: `idx_reservations_time_range (start_time, end_time)` — 期間検索・重複判定用。

## 5. ビジネスルール / バリデーション

予約の作成・編集時に、フロント（UX）とバックエンド（正）の両方で検証する。

| ルール | 内容 | エラーコード |
|---|---|---|
| タイトル必須 | 空白のみは不可 | `INVALID_TITLE` |
| 時間の前後関係 | `end_time > start_time` | `INVALID_TIME_RANGE` |
| 過去日時の禁止 | 開始・終了ともに現在時刻より未来 | `PAST_DATE_TIME` |
| 営業時間内 | 9:00〜22:00 に収まり、かつ**同一日内**で完結 | `OUTSIDE_BUSINESS_HOURS` |
| 重複禁止 | 同時間帯に `confirmed` の予約が存在しない（編集時は自レコード除外） | `OVERLAPPING_RESERVATION` |
| 権限 | 編集・キャンセルは作成者本人のみ | `RESERVATION_NOT_FOUND` |

- 重複判定: `start_time < 新end AND end_time > 新start`（端が接する予約は許容）。
- 時間帯の境界判定はすべて Asia/Tokyo で行う。

## 6. API 仕様

ベースURL: `http://localhost:8080`。認証が必要なエンドポイントはセッション Cookie 必須。

### エンドポイント一覧

| Method | Path | 認証 | 説明 |
|---|---|---|---|
| GET | `/login` | – | Google OAuth 開始（リダイレクト） |
| GET | `/callback` | – | OAuth コールバック（フロントへリダイレクト） |
| GET | `/api/me` | 必要 | ログインユーザー情報 |
| PUT | `/api/me` | 必要 | 表示名の更新 |
| POST | `/api/logout` | 必要 | ログアウト |
| POST | `/api/reservations` | 必要 | 予約作成 |
| PUT | `/api/reservations?id=` | 必要 | 予約編集 |
| GET | `/api/reservations?month=YYYY-MM` | 必要 | 月単位の予約一覧 |
| GET | `/api/reservations?start=&end=` | 必要 | 期間（週）指定の予約一覧 |
| GET | `/api/reservations?date=YYYY-MM-DD` | 必要 | 日単位の予約一覧 |
| GET | `/api/reservations/me` | 必要 | 自分の予約一覧（`confirmed`、開始降順） |
| PUT | `/api/reservations/cancel?id=` | 必要 | 予約キャンセル |

> `GET /api/reservations` はクエリ（`month` / `start`+`end` / `date`）で分岐。いずれも無い場合は 400。

### 主要リクエスト/レスポンス

**予約作成** `POST /api/reservations`

```jsonc
// Request
{
  "title": "面接",
  "start_time": "2026-07-15T10:00:00+09:00",
  "end_time": "2026-07-15T11:00:00+09:00",
  "notes": "",
  "add_to_google_calendar": false   // 任意。true で本人カレンダー連携
}
// Response 200
{
  "status": "success",
  "id": 12, "user_id": 3,
  "title": "面接",
  "start_time": "...", "end_time": "...",
  "notes": "",
  "created_at": "...", "updated_at": "...",
  "google_calendar": "added"        // add_to_google_calendar=true のときのみ
}
```

**予約一覧（期間）** `GET /api/reservations?start=&end=`

```jsonc
// Response 200 — 予約者名を含む
{
  "status": "success",
  "data": [
    {
      "id": 12, "user_id": 3,
      "title": "面接",
      "start_time": "...", "end_time": "...",
      "status": "confirmed",
      "notes": "",
      "user_name": "山田太郎"
    }
  ]
}
```

**表示名更新** `PUT /api/me`

```jsonc
// Request
{ "name": "新しい表示名" }
// Response 200
{ "id": "3", "email": "...", "name": "新しい表示名", "picture": "..." }
```

### エラーレスポンス

```jsonc
{ "status": "error", "code": "OVERLAPPING_RESERVATION", "message": "この時間帯には既に予約があります" }
```

| HTTP | code | 発生条件 |
|---|---|---|
| 400 | `INVALID_TITLE` | タイトル未入力 |
| 400 | `INVALID_TIME_RANGE` | 終了 ≤ 開始 |
| 400 | `PAST_DATE_TIME` | 過去日時 |
| 400 | `OUTSIDE_BUSINESS_HOURS` | 営業時間外・日跨ぎ |
| 401 | – | 未ログイン（`unauthorized`） |
| 404 | `RESERVATION_NOT_FOUND` | 対象なし・編集権限なし |
| 409 | `OVERLAPPING_RESERVATION` | 時間帯の重複 |
| 500 | `INTERNAL_ERROR` | サーバー内部エラー |

## 8. セキュリティ上の注意（本番前の課題）

- OAuth の `state` が固定値（`"random"`）。本番ではセッションごとにランダム生成すべき。
- `docker-compose.yaml` に `GOOGLE_CLIENT_SECRET` が直書き。環境変数/シークレット化が必要。
- OAuth の `RedirectURL` が `http://localhost:8080/callback` 固定。環境別に切替が必要。
- CORS 許可 Origin が `http://localhost:3000` 固定。
- `SECRET_KEY` の既定値（compose 上）は開発用。本番は強固な値に。
