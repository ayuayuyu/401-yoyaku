# loop-audit — Loop Readiness Score

ループを走らせる前に、その LOOP.md が「安全に自走できる設計か」を採点する。
自己採点による暴走・理解負債を防ぐゲート。**起動前に必ず通す**。

## 引数

- `$1` = 対象 `LOOP.md` のパス（例 `loops/pr-guardian/LOOP.md`）。
  未指定なら `loops/*/LOOP.md` を列挙し、対象を1つ選ばせる（全部監査も可）。

## 採点ルーブリック（各項目を 0 / 半分 / 満点で評価）

| 配点 | 項目 | 満点の条件 |
|---|---|---|
| 20 | **Goal** | 結果ベースで1〜2文、手段を目的化していない |
| 25 | **Definition of Done（停止条件）** | 機械的に検証可能。曖昧語なし。「STOP」が一意に決まる |
| 15 | **Verification（検証者）** | 具体コマンドがあり、**別モデル**での採点が明記されている |
| 10 | **Cadence** | 起動方法・間隔/トリガーが明確 |
| 10 | **Guardrails** | 最大反復数・連続失敗時の停止/エスカレーション・禁止操作・コスト上限が揃う |
| 10 | **Isolation** | worktree の要否が判断され記述されている |
| 10 | **Connectors + Memory** | 使うコネクタと前提、STATE.md/lessons への導線がある |

合計 100。**判定: 85+=Green（起動可）/ 70–84=Yellow（軽微な補強推奨）/ 70未満=Red（起動非推奨）**。

## 出力

1. スコア表（項目ごとの点数と一言講評）。
2. 総合 Score と Green/Yellow/Red 判定。
3. **不足項目の具体的な直し方**（例: 「DoD の『レビュー対応済み』を『未 resolve のレビューコメント 0 件』に置き換える」）。
4. Red の場合は「このまま起動しないこと」を明示し、loop-init 相当の補強を促す。

## 原則

- 忖度しない。曖昧な停止条件は減点し理由を書く。
- LOOP.md の**編集はしない**（採点と提案のみ）。修正はユーザー/loop-init に委ねる。
