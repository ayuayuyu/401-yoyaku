# loop-sync — ドリフト（理解負債）検知

記事の警告「コードを読まないと理解負債が返済不能になる」に対する歯止め。
STATE.md が語る「現在地」と、リポジトリの実状態が一致しているかを機械的に照合する。

## 引数

- `$1` = 対象ループ名 or `STATE.md` パス。未指定なら `loops/*/` を列挙して選ばせる。

## 照合する項目

1. **作業ツリー**: `git status --porcelain` と `git diff --stat`。STATE の「変更した」記述と実差分が一致するか。
2. **テスト/ビルドの主張**: STATE が「テスト通過」等と書いていたら、根拠を実行して再確認する。
   - バックエンド: `cd backend/src && go test ./... && go vet ./...`
   - フロント: `cd frontend && pnpm lint && pnpm build`
   - SQL 変更があれば `cd backend/src && sqlc generate` 後に `git diff --exit-code` で未再生成を検知。
3. **DoD チェック**: STATE.md のチェックボックスが「実際に満たされているか」を検証結果と対照。
4. **反復/上限**: 反復回数がガードレールの上限に近い/超えていないか。
5. **鮮度**: 「最終更新」が古すぎないか（放置ループの検知）。

## 出力

- ✅ 一致した項目 / ⚠️ 乖離した項目（STATE の主張 vs 実際）を対比表で示す。
- 乖離があれば「STATE.md を実態に合わせて直す」具体案を提示する（勝手には直さず提案）。
- 重大な乖離（例: 「done」なのにテスト失敗）は **STOP 推奨**として強調する。

## 原則

- STATE.md/LOOP.md は編集しない（検知と提案のみ）。
- コマンド実行は読み取り・検証系のみ。デプロイ・push・DB 破壊は行わない。
