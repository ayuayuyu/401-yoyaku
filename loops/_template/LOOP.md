# LOOP: <ループ名>

> ループの「憲法」。人間が目的・境界・停止条件を書き、ループはこれに従って自走する。
> ここに書かれていないことは勝手にやらない。迷ったら停止して人間に確認する。
> このファイルは頻繁には変えない（変えるのは STATE.md）。

## Goal（目的）

<このループが達成すべき状態を1〜2文で。手段ではなく「結果」を書く。>
例: 対象 PR を「CI 緑・レビュー指摘対応済み」の状態に保つ。

## Definition of Done（停止条件）

> すべて満たしたら **STOP**。ループはこの条件だけを見て終わる。曖昧な条件は書かない。

- [ ] <条件1: 機械的に検証できる形で>
- [ ] <条件2>
- [ ] <条件3>

## Non-Goals / やらないこと

- <スコープ外1: 例「本番デプロイはしない」>
- <スコープ外2>

## Cadence（スケジューリング｜要素1）

- 起動方法: `/loop <間隔> <このLOOP.mdを参照する指示>`（例: `/loop 5m loops/<名>/LOOP.md に従って進めて`）
- 間隔/トリガー: <例: 5分ごと / PR 更新時 / 手動>
- 稼働時間帯の制限: <例: 平日日中のみ / なし>

## Verification（検証者｜要素4）

> **必ず本体とは別モデルで採点する。** `/loop-verify <名>` が loop-verifier
> サブエージェント(model: sonnet)を呼び、下記コマンド結果と STATE を DoD に照合する。

- 検証コマンド:
  - `<例: cd backend/src && go test ./... && go vet ./...>`
  - `<例: cd frontend && pnpm lint && pnpm build>`
- 合格基準: 上記すべて成功 かつ DoD 全項目が客観的に満たされること。

## Isolation（隔離ワークスペース｜要素3）

- worktree を使う: <yes/no>
- 使う場合: `git worktree add ../<名>-wt <branch>` で隔離し、他ループと衝突させない。

## Connectors（コネクタ｜要素6）

- 使用ツール: <例: gh CLI（PR/CI/コメント）, Slack Webhook, MCP: ...>
- 認証/前提: <例: `gh auth status` が通っていること>

## Guardrails（ガードレール／安全装置）

- 1 起動あたり最大反復数: <例: 5>
- 同一失敗が連続したら: <例: 2 回で停止し人間へエスカレーション>
- 禁止操作: <例: force push / main への直接 push / 破壊的マイグレーション>
- コスト上限（目安）: <例: 1 起動 あたり 〜X トークン / 超えたら停止>
- エスカレーション先: <例: STATE.md に BLOCKED を書いて停止＝人間待ち>

## Memory（永続メモリ｜要素5）

- 進捗と引き継ぎ: `STATE.md`（毎反復更新）
- 学び・再発防止: `tasks/lessons.md`
